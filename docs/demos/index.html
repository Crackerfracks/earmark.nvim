earmark.nvim, feature by feature

The idea. earmark lets you label spans of text in Neovim with colours, the way you would mark up a printed page with highlighters. Labels are numbered (and can be named), so 3ghiw means "mark this word with label 3".

Marks stay on the text. Edit around them, reformat the file, change it in another program, undo: each annotation stays on its words. If the words themselves are rewritten it is marked stale; if they are deleted it is detached and kept, so nothing is silently lost.

Notes on labels. Any annotation can carry a Markdown note with #tags; a small hover shows it when the cursor rests there, and pickers, the quickfix list and a Markdown export find it again.

How to read the clips. The blue bar at the top says what the clip shows. The box under the editor shows a note for the current step and, on the yellow line, the keys as they are typed, one at a time (<leader> is Space). Each step waits a moment before the keys, so you can read the note, and holds the result a few seconds; the keys stay up until the next step starts. Every clip uses earmark's default settings unless its card says otherwise. Boxes marked like this one call out a default you are asked to confirm:

Default to confirm (item N): … (the numbers are the list at the end of the README, under "Status").

Try it yourself. Run make demo in the repository, then cd /tmp/earmark-demo/proj && nvim -u ../init.lua notes/essay.md (open the other files with :e notes/fresh.md and :e notes/changed.md). It is the same project the clips were recorded in, with the same theme; nothing from your own config is loaded. Run make demo again to reset it.

Comments. Every card has a Comment button (or click anywhere on a card in comment mode). Type what you think, about a default, a bug, the clip itself, and press Send to Claude to put it straight into the working session's prompt; a plain comment stays on the page for later.

Annotate

Marking text with a label: the operator gh, with or without a count.

A count picks the label

GIF · MP4 · still

What you are looking at: The word "library" turns label 3's colour; then a whole line segment takes label 12. The statusline swatch at the bottom right shows the label the next gh uses.

Why it matters: This is the fast path: the count is the label, so marking text is one motion, like any Vim operator.

When the text changes

Annotations stay attached when the text is edited, reformatted or changed outside Neovim. When the annotated text itself is rewritten, the annotation is stale; when it is gone, detached, never dropped.

Edits, deletes and undo

GIF · MP4 · still

What you are looking at: Annotations move down with the text; deleting the line removes its highlight; undo brings it back.

Why it matters: Highlights that break on every edit are useless; these follow the text.

Try it yourself in notes/essay.md:
  1. on line 3 3G
  2. insert a line above OA new first line.<Esc>
  3. delete an annotated line jdd
  4. undo u

Edits outside Neovim

GIF · MP4 · still

What you are looking at: The file was changed behind Neovim's back, then reloaded with :e. Every annotation moves down with its words; nothing is left behind at the old places.

Why it matters: Formatters, git checkouts and other editors change files under you; the marks follow the text.

Default to confirm (item 8): text snapshots in .earmark/snap/ are gitignored, so a fresh clone re-anchors by quote and context only.

Try it yourself in notes/essay.md:
